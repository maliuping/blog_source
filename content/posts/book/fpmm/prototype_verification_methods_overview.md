fpmm 总共介绍了 **5 种** 具体的原型验证方法：

1.  **虚拟平台 (Virtual Platforms)**：
    这是在项目最早阶段即可使用的原型。它们是 SoC、电路板、虚拟 I/O 和用户界面的全功能但时序松散（loosely-timed）的软件模型，运行在主机仿真环境中。其优势在于极高的系统可见性和控制力，且易于分发给多位用户。

2.  **SDK（软件开发工具包）**：
    这是非常通用的原型验证环境（如 iPhone SDK）。其目标是提供“足够的精度”来欺骗应用程序，使其认为运行在最终平台上。开发者通常在高级 API 之上进行编程，代码首先在主机上编译验证，之后再针对目标处理器重新编译。

3.  **FPGA（基于 FPGA 的原型验证）**：
    在设计流程后期但早于真实硅片可用。它是 SoC、电路板和 I/O 的全功能硬件表示，使用与 SoC 相同的 RTL 代码。其核心优势是运行速度快（可达数十 MIPS）且具有 RTL 级的精度，能够连接真实外部接口进行测试。

4.  **硬件仿真器 (Emulators)**：
    另一种硬件辅助手段，侧重于自动化映射而非执行性能。它具有更短的编译时间和高度自动化的 RTL 映射流程，但运行速度通常低于 1 MIPS。由于速度慢且成本极其昂贵，它常被视为仿真环境的加速扩展，主要用于短时任务（如 Boot ROM 调试）。

5.  **首片硅片 (First Silicon)**：
    在真实芯片流片回来后，利用首批样品制作的原型板。虽然它的执行速度最快（实时）且精度 100%，但在设计流程中出现最晚，无法为软件开发提供领先优势。此外，其内部调试可见性非常有限。

这些方法在**可用时间、执行速度、精度、容量、开发成本和调试能力**等维度上各有利弊，用户需根据项目优先级进行选择。
